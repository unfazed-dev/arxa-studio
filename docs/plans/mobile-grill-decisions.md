# arxa studio mobile grill — decision log

Scope: iOS + Android native apps for arxa studio (Tauri v2 mobile), phone as a
client of the Mac-hosted engine. Companion to
`docs/plans/arxa-studio-grill-decisions.md` (desktop, closed through D35).

## Settled

- **M1 — Transport: iroh, embedded.** Phone ↔ Mac engine over iroh P2P
  (QUIC, hole-punching, relay fallback). No Tailscale/headscale dependency —
  researched and rejected: third-party coordination server + per-device VPN
  setup is the wrong UX for a consumer-grade pairing flow. iroh embeds in
  both the engine (Mac) and the mobile app.

- **M2 — Pairing: QR minted by the desktop app.** Register/sign-in on mobile
  is exclusively by scanning a QR code generated by arxa studio desktop.
  The QR carries the iroh node addr + a one-time enrollment secret;
  devices are revocable from the desktop.

- **M3 — Device count: unlimited.** Any number of phones may pair to one
  engine.

- **M4 — Surface: full studio.** The mobile app is the full studio, trimmed
  per-view only where a surface genuinely cannot work on mobile — decided
  as we go, not upfront. Native iOS/Android app, not a web wrapper.

- **M5 — Distribution: TestFlight + APK sideload** for now; store release is
  a later decision.

- **M6 — Fallback + no-database users.** Server-side fallback exists for
  reachability (relay), but: the Supabase database belongs to Arxa Digital
  Solutions (parent company) — arxa studio does NOT provide database
  hosting to its users. Free users without any database must get the exact
  same mobile experience via local secure storage on the engine side.
  Decoupling per D32–D35 (BYO provider abstraction) applies unchanged.

- **M7 — Push: standalone `cairn-pushd` as a studio-managed sidecar.**
  (Settled 2026-08-26.) The engine supervises cairn-pushd exactly like its
  other sidecars — one binary, SQLite token registry, no Postgres/sync
  engine required. Users never install or manage it. APNs/FCM credentials
  live in engine-local config, consistent with M6 (no hosted infra for
  free users). The client half is already done: `cairn_tauri` gained
  `register_push_token` / `deregister_push_token` + sign-out cleanup
  (ADR-0037 contract, landed on top of cairn `e50f791`).

- **M8 — Offline data: online-only v1, cairn_tauri offline-first later.**
  (Settled 2026-08-26.) v1 requires engine reachability (iroh relay covers
  most gaps). No bespoke cache/queue — that would be throwaway sync logic.
  Offline-first arrives when the agent-owned cairn_tauri work
  (`cairn:docs/plans/cairn-integration-tauri-flutter-push.md`) lands and
  is integrated.
